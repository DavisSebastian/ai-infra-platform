C++ in the gateway: a thread is not enough

The gateway now cleans every prompt in C++, bound to Python with pybind11. It made the gateway no faster: a prompt cleans in 2.4 µs against 2.73 s of inference. What it did teach: native code can freeze an async server from any thread, random testing finds what examples miss, and native code has to be built where it runs.

The big picture

Python for orchestration, a compiled library for the hot loop.

The rules: remove invisible characters (zero-width spaces, bidi overrides) and control characters, collapse whitespace, cap the length if asked. The zero-width joiner is kept, because emoji are built from it.

Is this normal?

Writing your own C++ inside a web service is rare: profiling usually points at the network, the database or the model. Using native code is universal: FastAPI's validation (pydantic-core) is Rust, uvloop and the HTTP parsers are C. In AI infra, native code lives in libraries: tokenizers, vLLM, PyTorch extensions, Triton backends.

1When native code helps

It's about what the inner loop touches, not the language.

Removing 5 characters from 9.6 million, four ways:

ApproachTime
Hand-written Python loop135 ms
str.translate with a dict (written in C)358 ms: slower than the loop
Regex (C)37 ms
str.replace × 5 (C)7 ms

translate is written in C but looks up every character in a Python dict, so it still pays the per-object cost. replace scans raw memory. The rule: fast code is code whose inner loop touches no Python objects.

2What an extension is

A compiled library Python loads like a plugin.

import promptclean loads _native.cpython-312-darwin.so: 145 KB of machine code. The filename is a contract: CPython 3.12, macOS. It won't load on Linux. pybind11 writes the glue (type conversion, reference counting, exceptions) that the raw C API would make you write by hand.

Java analogy

JNI, without the boilerplate: a native library, loaded at runtime, called like a normal method.

The main correctness trap.

The C++ decodes 1 to 4 bytes per character, and the length cap counts characters, so it can never split one.

4A thread is not enough

Week 2's freeze, in native code.

Moving the call to a worker thread changed nothing until the C++ released the GIL.

A worker thread inside C++ still holds Python's GIL, and the event loop needs it to run any Python. The binding now releases it: py::call_guard<py::gil_scoped_release>(). That's safe because pybind11 copies the input before the guard and builds the result after it. The 12 ms left is converting the 20 MB result back into a Python string.

Why Week 2 didn't hit this

to_thread(model.generate) worked because PyTorch releases the GIL inside its heavy operations. Our C++ didn't, until it was told to.

5The bug only random input found

A readable reference, and a property test against it.

The rule tests run against both the Python reference and the C++. A property test (hypothesis) feeds 6,000 random strings, weighted toward the tricky characters, and requires identical output. Six realistic C++ bugs were planted: all were caught. One, a control-character range off by one, was missed by all 21 hand-written examples and caught only by random input.

And one real bug, found by a failing test

A lone surrogate ("\ud800", legal in JSON) crashed the gateway. The fallback caught UnicodeEncodeError, but pybind11 raises TypeError. Test the failure path, not the error you expect.

The ratio is constant; the value isn't

Crossing into C++ costs ~0.3 ms per 10 MB, so C++ is 4× faster even on a prompt. But that saves 7.5 µs against 2.73 s of inference. It matters only for documents and datasets.

7In the gateway

Clean before taking a slot; thread only when it pays.

Prompts are cleaned before admission, so a big clean never holds the model's only slot. Under 64 K characters they're cleaned inline (a thread hop costs more than 2 µs); above, on a worker thread. A body that isn't a chat request is forwarded unchanged, and /health counts the characters removed.

8Built where it runs

Docker and CI compile the C++ themselves.

Multi-stage image

Compiler and CMake in the builder stage only. The image stays 293 MB, with no compiler inside.

CMake from Debian

The first build spent 3 minutes failing to download CMake from PyPI. Now it's installed with the compiler; the compile takes 2.5 s.

A build matrix

The tests run on Linux (gcc, x86_64) and macOS (clang, arm64): native code must work wherever it's compiled.

Pinned build tools

uv.lock doesn't cover build dependencies, so scikit-build-core and pybind11 are pinned exactly.
